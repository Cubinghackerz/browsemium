# 2.3 — Smart space routing

Status: implementation plan, not shipped. Start after the quality gates in
`QUALITY_PASS.md`; do not enlarge BrowserWindowModel beyond small wiring calls.

## Scope and boundaries

- Profile-local domain → existing space rules. Exact host matching by default;
  subdomains require an explicit option and suffix-boundary matching.
- Normalize domains once; reject schemes, ports, paths, credentials, empty
  hosts, and ambiguous wildcard rules. A pure matcher owns precedence.
- New small repository/coordinator files; reuse existing group/tab operations.
  Settings and the shared tab context menu create, edit, and remove rules.
- Route only committed HTTP(S) main-page navigation of an active, ordinary tab
  in the initial version. Do not route private windows, previews, background
  tabs, or mutate split-pane membership implicitly. Explain deferred routing
  in split view instead of claiming that path is supported.
- Resolve source/target/profile again at action time. A locked target receives
  an explicit route/unlock choice; authenticate first and move only after a
  current successful grant. Never move the tab before an unlock completes.
- Show a notice with Undo. Capture the original space/folder membership before
  moving. Undo must validate current membership and surviving destinations;
  never silently unlock, resurrect deleted spaces, or overwrite newer moves.
- Profile switch, tab close, or a newer navigation cancels stale pending work.
  Rules/undo state must not bleed between profiles or private windows.

## Test-first acceptance

Generated fixtures: host normalization and sibling-host attacks; exact vs
subdomain precedence; private/peek/background/split exclusions; locked refusal;
unlock denial/cancellation; profile change during unlock; one successful move;
undo and deleted destinations; persistence failure; no routing loop on reload.
Drive integration through the existing fake engine/authenticator, not real
Touch ID or websites. Confirm each regression red → green → reverted-red.

## Delivery

One verified matcher/repository unit, then coordinator integration, then native
Settings/context-menu/Undo UI. Run focused tests per unit, full package suite
once for the workstream, headless/project/app gates, and native light/dark QA.
Only then change the roadmap status and product claims.
