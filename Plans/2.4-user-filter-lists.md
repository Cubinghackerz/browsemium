# 2.4 — User filter lists

Status: implementation plan, not shipped. Extend ContentRuleListManager; keep
the bundled starter list and its existing license contract intact.

## Scope and boundaries

- Import a user-selected ABP/AdGuard text file or an explicitly entered HTTPS
  source. No automatic subscriptions, bundled third-party lists, or arbitrary
  protocols. Background refresh requires a separately enabled schedule.
- Use bounded, cancellable downloads with no ambient cookie/credential store.
  Recheck redirect scheme; validate encoding and size before parsing.
- Pure conversion in a small new module, with supported syntax documented.
  Count accepted/skipped rules and report unsupported constructs honestly.
  Respect WebKit's regex restrictions; do not emit unsupported alternation.
- Parsing/compilation happens off the UI critical path. Use profile/list/hash
  identifiers for compiled artifacts. Stage → validate → compile → commit;
  never replace a last-good list with a failure, empty parse, or stale task.
- New views receive the same last-good profile configuration as existing
  views. Profile switches cancel results from the previous profile. Private
  windows may apply existing blocking, but never persist subscription edits.
- UI states: fetching, parsing, compiling, active, and failed-with-last-good.
  Counts describe rules, never blocked requests. Errors omit list contents,
  credentials, and sensitive URL query values.
- User-supplied lists are not redistributed. Any later bundled list requires
  recorded license review in ThirdPartyNotices before inclusion.

## Test-first acceptance

Generated ABP/AdGuard fixtures; unsupported syntax and malformed regex;
size/encoding rejection; HTTPS redirect refusal; cancelled/stale compilation;
failure retains last-good; atomic metadata commit; profile/private isolation;
WebKit compilation of representative output; no fictitious request counts.
Inject fetching/compilation adapters so tests make no remote requests.

## Delivery

Converter and bounds, repository/last-good transaction, async manager wiring,
then Settings. Each coherent unit has focused regression checks; one complete
workstream suite plus native loading/error/light/dark QA precedes release.
