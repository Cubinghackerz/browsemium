# 2.4 — User filter lists

Status: converter/bounds and profile-local last-good persistence implemented
and fixture-tested, not released. Runtime wiring and Settings remain open.
Extend ContentRuleListManager; keep the bundled starter list and its existing
license contract intact.

## Initial conversion subset

- ASCII hostname rules `||host^`, including subdomains and ports, and simple
  request exceptions `@@||host^`. Exceptions follow blocks within the same
  converted list. One regex per host; no regex alternation.
- Positive resource qualifiers: image, script, stylesheet, font, media,
  xmlhttprequest, and document (document is block-only). Qualifier order and
  hostname case are canonicalized before duplicate detection.
- Unsupported patterns, cosmetic/scriptlet rules, negated resources, domain
  qualifiers, party qualifiers, redirects, and page-wide document exceptions
  are skipped with line numbers and closed reason codes, never source text.
  No unsupported modifier is dropped to create a broader rule.
- Includes and conditional directives reject the entire conversion. Nothing
  is fetched, evaluated, or executed by the converter.
- Hard ceilings: 4 MiB UTF-8 input, 100,000 lines, 2,048 bytes per line,
  50,000 accepted rules, and 16 MiB output. Empty supported output, oversized
  input, and cancellation return failures rather than replacement lists.
  UTF-8 BOM and CRLF are supported. Tests use generated fixtures only and
  include compilation by the real WKContentRuleListStore.

Party modifiers deliberately remain unsupported: [WebKit's load-type
classification](https://webkit.org/blog/3476/content-blockers-first-look/)
uses security origins, which does not faithfully reproduce [AdGuard's
party semantics](https://adguard.com/kb/general/ad-filtering/create-own-filters/).
This is a limited subset, not full ABP/AdGuard compatibility.

## Last-good persistence contract

`UserFilterListRepository.prepare` does not write. It gives the compiler a
profile/list/SHA-256 identifier and an immutable payload. Commit requires that
exact compilation identifier and the expected revision; metadata, payload,
and the revision ledger update atomically. Update, toggle, or removal makes
older candidates stale. Deleted IDs retain only a revision record so a late
original candidate cannot recreate a deleted list.

Each profile has its own table. Read-only clients reject all edits. Totals
include disabled lists and are bounded to 10 lists, 50,000 rules, and 16 MiB
of rule JSON. SQL parameters are bound; errors contain no raw SQL, input
lines, or source URLs. Only source kind is stored, not URLs or credentials.
Generated fixtures cover rollback/retry, stale completion, private-style
read-only access, cross-profile rejection, deletion replay, and total limits.
Runtime must enforce these contracts before this becomes an app feature.

## Scope and boundaries

- Import a user-selected ABP/AdGuard text file or an explicitly entered HTTPS
  source. No automatic subscriptions, bundled third-party lists, or arbitrary
  protocols. Background refresh requires a separately enabled schedule.
- Use bounded, cancellable downloads with no ambient cookie/credential store.
  Recheck redirect scheme; validate encoding and size before parsing.
- Pure conversion in a small new module, with supported syntax documented.
  Count accepted/skipped rules and report unsupported constructs honestly.
  Respect WebKit's regex restrictions; do not emit unsupported alternation.
- Parsing/compilation happens off the UI critical path. Use profile/list/hash
  identifiers for compiled artifacts. Stage → validate → compile → commit;
  never replace a last-good list with a failure, empty parse, or stale task.
- New views receive the same last-good profile configuration as existing
  views. Profile switches cancel results from the previous profile. Private
  windows may apply existing blocking, but never persist subscription edits.
- UI states: fetching, parsing, compiling, active, and failed-with-last-good.
  Counts describe rules, never blocked requests. Errors omit list contents,
  credentials, and sensitive URL query values.
- User-supplied lists are not redistributed. Any later bundled list requires
  recorded license review in ThirdPartyNotices before inclusion.

## Test-first acceptance

Generated ABP/AdGuard fixtures; unsupported syntax and malformed regex;
size/encoding rejection; HTTPS redirect refusal; cancelled/stale compilation;
failure retains last-good; atomic metadata commit; profile/private isolation;
WebKit compilation of representative output; no fictitious request counts.
Inject fetching/compilation adapters so tests make no remote requests.

## Delivery

Converter and bounds, repository/last-good transaction, async manager wiring,
then Settings. Each coherent unit has focused regression checks; one complete
workstream suite plus native loading/error/light/dark QA precedes release.
