Browsemium 2.0. Profiles, tab groups, reader mode, local models, and an importer that brings every profile with you.

**Updating from 1.0.2:** your data is moved into a "Personal" profile automatically on first launch. The migration is transactional, verifies every row count, and leaves `browsemium-pre2.sqlite` beside the database as a backup. Nothing is deleted from the original file until the copy is verified.

## Profiles

Every profile gets its own cookies, logins, history, bookmarks, tabs, passwords, and WebKit data store. Work and personal stay completely separate on the same Mac. Switch from the toolbar chip; create, rename, and delete from Settings, where deleting the active profile falls back safely. API keys are stored per profile in the keychain.

## Import that handles every profile a browser has

Chrome, Brave, Edge, Vivaldi, Arc, Chromium, Firefox, and Safari are detected. When a browser holds several profiles, each is found, named the way you named it (from `Local State` / `profiles.ini`), and can be imported into its own new Browsemium profile. Grant a browser folder once and every profile inside it imports without another prompt. Bookmarks keep their folders, history imports up to 5,000 recent entries, Safari's reading list and Chromium's default search engine come along, and Chromium-family passwords go straight into your keychain. Firefox and Safari passwords are not importable, and the app says why. Cookies are never imported.

## New in the browser

- **Tab groups**: a picker at the head of the strip switches groups as a set, with colours, rename, and delete. Closing a tab picks its neighbour inside the same group.
- **Multiple windows** (⌘N), each with its own tabs.
- **Reader mode** (⇧⌘R): the article as clean text, with font sizing and an "always open this site in Reader" preference.
- **Tab switcher in the command palette** (⌘K): type a few letters of any open tab.
- **Audio indicators**: a speaker appears on tabs that are playing; click to mute. Best-effort by design, since WebKit exposes no public per-tab audio API.
- **Default browser**: make Browsemium the handler for links from other apps, with a System Settings fallback.
- **Right-click a selection** and choose "Ask Browsemium AI About Selection" to attach it in the dock.

## Assistant

- **Ollama support**: run models locally with no key and no account. Nothing leaves the Mac.
- **Saved conversations** per profile, with a chats menu in the dock and restore-on-launch.
- **Draggable captures**: drag a screenshot chip straight into the provider's composer, or send and press ⌘V. Captures appear as thumbnail chips the moment they are taken.

## Reliability

- Fixed the crash that took down 1.0.1: a memory-pressure handler touched main-actor state from a background queue.
- The release process now kills the built app with SIGKILL, relaunches it, and verifies the session survived before a DMG can be packaged.
- The dock resize no longer jitters; the drag measures in window coordinates.
- Fixed a missing runtime search path that would have stopped the embedded updater from loading.

## Install

Terminal installer (no Gatekeeper prompt, checksum verified against browsemium.vercel.app):

    curl -fsSL https://browsemium.vercel.app/install.sh | bash

Homebrew:

    brew install --cask cubinghackerz/tap/browsemium

DMG: download below, drag to Applications, then allow it once under System Settings, Privacy & Security, Open Anyway. This build is signed ad-hoc rather than with a Developer ID, which is why macOS asks once. It is a missing certificate, not a detection.

## Honest limits

- No rendering-speed claims. Browsemium gets you to an answer sooner; it does not claim to paint pages faster.
- No per-tab memory numbers and no blocked-item counter: WebKit does not expose either, so neither is invented.
- Audio detection is best-effort (see above).
- Extra windows are not restored after a relaunch; the first window's tabs are.
- No account, no sync, no telemetry. Browsing data stays on this Mac.
