# Browsemium 2.1.1

A preview release: a redesigned AI dock with more reliable replies, imported
filter lists, and an opt-in way for an external MCP client to work in a
Browsemium task under your control. This build is ad-hoc signed and **not
notarized**.

## AI dock

- Replaced the cramped API-key row with a readable secure field and connection
  card. Connection options and model refresh are grouped together once connected.
- Added page-aware starting actions and one multiline composer containing
  attachment and skill menus, with explicit Review/Stop controls. Review is
  unavailable while context is being prepared. API messages still require review.
- Private, locked and unsupported pages do not expose page-context actions.
- Empty replies become a visible, retryable error instead of a permanent
  spinner, and stalled requests stop after two minutes.
- Gemini handles finish frames without content, reports rejected answers,
  separates thought parts from answer text, and lists only models that
  advertise content generation.
- Old empty assistant records are filtered when loading a conversation and
  building a request, without deleting stored records. Stop preserves earlier
  replies. These behaviors use fixture tests; live credential QA is open.

## External agent preview (opt-in, off by default)

- Settings → Agent turns on a loopback-only (127.0.0.1) MCP endpoint, with a
  bearer token stored in Keychain that you can copy and reset. Nothing listens
  until you enable it. It works with MCP clients that support Streamable HTTP
  and custom headers; the card shows a ready-to-paste Claude Code command.
- A client must request a task; you approve a card naming the origins and limits.
  Work happens in separate task tabs with a Stop button. Every click and every
  typed value needs your confirmation; password, payment and one-time-code
  fields are refused, and navigation outside the granted origin is refused.
- Stop, switching profile, locking a space and quitting end the task and close
  its pages. Task pages share your profile's browsing data and open in a panel,
  not a sidebar space. The client's self-reported name is not verified.
- The WebKit app gains the sandbox `network.server` entitlement, used only when
  you enable the endpoint. Page text a client reads may be forwarded to its model.
- The AI dock itself still cannot operate pages.

## Filter lists and the site shield

- Profile-local user filter lists are restored on launch and compiled through a
  staged path that keeps the working set on any failure. Settings accepts an
  explicitly chosen UTF-8 file or HTTPS address (4 MiB limit), with rule counts,
  re-import, enable/disable and confirmed removal. This is a limited hostname
  subset, not full ABP/AdGuard compatibility. No third-party list is bundled.
- The shield reports distinct named hosts in the installed lists. These are list
  sizes, never blocked-request counts.

## Imports and commands

- Browser-key queries no longer show authentication dialogs; protected keys are
  not bypassed. A password CSV import keeps its destination profile and saves
  passwords to Keychain. Passwords are no longer whitespace-trimmed on save.
- The command palette gained print, find in page, Reader mode and hide element.

## Install

Terminal installer (release manifest, SHA-256, DMG integrity, signature,
sandbox, and architectures verified):

    curl -fsSL https://browsemium.vercel.app/install.sh | bash

If macOS blocks the first launch, allow it once in System Settings → Privacy &
Security → **Open Anyway**. Developer ID signing, notarization, Sparkle updates
and the Homebrew cask return when signing credentials are available.

## Honest limits

- No memory or speed comparison is claimed; the memory gate remains open.
- A live external-client session, the agent endpoint in the packaged app, and
  native keyboard/VoiceOver checks have not been verified by hand.
- Whole-app light/dark QA and logged-in site compatibility checks remain open.
