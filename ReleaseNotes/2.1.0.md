# Browsemium 2.1.0

This release fixes features that were advertised but did not work, and makes the
memory saver respect what a tab is actually doing.

## Memory saver

- A tab that is playing audio, holding a microphone or camera, downloading a
  file, or marked to stay loaded is no longer unloaded. The memory saver was
  checking only an empty signal list, so a background call or a download could
  disappear mid-flight.
- Right-click a tab and choose **Keep This Tab Loaded** to exempt it until you
  close it or turn the exemption off.
- Tabs that are unloaded now show as sleeping in the tab strip, in the hover
  card, and in Settings. That state never reached the interface before.
- **Free memory now** reports the app's measured footprint and says what it
  covers. The previous figure compared two readings of a number that could not
  include WebKit's page processes, so it was noise.

## Permissions

- Sites that ask for the camera or microphone now get a prompt: **Allow**,
  **Always allow**, or **Block**. WebKit denies these requests when the app does
  not answer them, so voice and video features on provider sites used to fail
  silently.
- Decisions are stored per profile and can be reviewed or removed in
  Settings → Site permissions.

## Extensions and profiles

- Chrome Web Store installs now require a valid CRX3 signature and matching
  store identifier before installation. Failed extension updates leave the
  previous working copy in place.
- Deleting a profile removes its WebKit website store and profile-scoped saved
  credentials before removing the profile record. If cleanup fails, the profile
  stays available for retry.
- Profile management now lives in Settings and the overflow menu. The duplicate
  profile control was removed from the toolbar.

## Privacy

- **Clear history when Browsemium quits** now clears history and closed tabs on
  quit. The setting was stored and shown but nothing read it.
- Settings → Privacy & Blocking can now clear cookies, site data, and cache for
  the active profile, or just the cache. Site data was previously unreachable
  from the app.
- The developer keychain workaround for WebKit's WebCrypto item is now opt-in
  (`BROWSEMIUM_CLAIM_WEBCRYPTO_KEY=1`). It never runs on its own, because
  replacing that item makes keys a site already stored undecryptable.
- Chrome Web Store pages use the Mac's preferred language when no language was
  explicitly selected, so a remembered site-language cookie no longer forces
  the store into an unexpected language.

## Reliability

- A second window (⌘N) opens reliably, and both windows receive tab, download,
  and permission updates. Previously the last window to open received every
  event and the others went quiet.
- The mandatory update gate can no longer sit on an empty spinner: a check that
  finds no update releases it.
- Favicons retry once when a site's icon is not ready on first load, and both
  favicon caches are bounded.
- The Downloads panel lists downloads in the order they started.
- The default-browser check uses the running bundle's identifier instead of a
  hard-coded one.
- Making Browsemium the default uses macOS's consent-aware registration flow.
- Search submissions keep the original query visible in the address bar while
  the matching results page is active.

## Benchmarks

The memory comparison harness was measuring the wrong things and is corrected:
it sums the launched process tree (name matching counted a second copy of the
browser and missed WebKit's page processes), attributes WebKit's page processes
by difference, refuses to run while another WebKit app is active, and points the
profile directory at a path inside the app's sandbox container, which the
sandbox allows and a system temp path does not. The 20% gate is unchanged.

## Install

Terminal installer (release manifest, SHA-256, DMG integrity, signature,
sandbox, and architectures verified):

    curl -fsSL https://browsemium.vercel.app/install.sh | bash

This build is ad-hoc signed and **not notarized by Apple yet**. If macOS blocks
the first launch, allow it once in System Settings → Privacy & Security →
**Open Anyway**. Developer ID signing, notarization, Sparkle updates, and the
Homebrew cask return when signing credentials are available.

## Honest limits

- No rendering-speed claims, and no per-tab memory numbers: WebKit does not
  expose either.
- Camera and microphone prompts cover what WebKit routes through the app;
  location and notifications are still handled by macOS.
- Audio and media-capture detection is best-effort, since it observes the page
  rather than an engine API.
